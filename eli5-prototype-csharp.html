C# creation pattern

Prototype

Create a new object by copying a prepared example.

1

Construction repeats work

Complex setup is slow, noisy, or easy to reproduce incorrectly.

2

Prepare once, then copy

Each copy starts with the prototype’s configured state.

3

Shallow copy can betray you

Editing A’s mutable list also changes B.

A new outer object does not guarantee new nested objects.

4

Define the copy contract

sealed class ReportTemplate { public List<string> Sections { get; } public ReportTemplate DeepCopy() => new(new List<string>(Sections)); }

An explicit name is clearer than ICloneable, whose Clone() does not promise shallow or deep copying.

5

Choose copy depth deliberately

Use Prototype when copying configured state is simpler than rebuilding it.

Remember

Prepared object→Copy by contract→Independent result
