The whole journey, when you want it
  1. Find: the browser finds a network address for the website name, often using DNS (Domain Name System).
  2. Connect: for our HTTP/1.1 example, TCP (Transmission Control Protocol) provides an ordered, reliable stream of bytes.
  3. Protect: HTTPS adds TLS (Transport Layer Security). It checks the server’s identity, establishes secret keys, and protects messages.
  4. Ask: an HTTP request names an action and a resource, with extra information and sometimes a body.
  5. Reply: the server returns a status, headers, and sometimes a body. The browser displays the page and may request more resources.

HTTP means Hypertext Transfer Protocol: agreed rules for web messages. HTTPS means HTTP Secure. HTTP/2 and HTTP/3 keep the request-and-response meaning but change how messages travel. HTTP/3 uses QUIC, a transport built on UDP (User Datagram Protocol), with TLS 1.3 integrated; it does not use TCP.

Sources & model limits

This is a simulation, not a real network or cryptography tool. Message snippets use readable HTTP/1.1 and omit some framing headers. The handshake models a fresh, certificate-based TLS 1.3 connection, without resumption or early data. A simplified route shows one server; real websites can use proxies and multiple servers.
