C# behavior pattern

Strategy

Put interchangeable algorithms behind one behavior contract.

1

The branching problem

Each new algorithm makes one class grow and retest old branches.

2

Extract the varying behavior

The context owns the workflow; a strategy owns one algorithm.

3

The C# shape

interface IRouteStrategy { Route BuildRoute(Point a, Point b); } sealed class RoutePlanner { private IRouteStrategy strategy; public Route Plan(Point a, Point b) => strategy.BuildRoute(a, b); }

Constructor injection can require a valid strategy from the start.

4

Swap behavior at runtime

Selection may come from the user, configuration, or another factory.

5

Know the boundary

A small switch may still choose the strategy; the algorithms no longer live inside it.

Use Strategy when one behavior varies independently and alternatives share a contract.
