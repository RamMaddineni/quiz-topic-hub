Beginner visual guide

Latency is the clock around one request.

From the client’s point of view, response time starts when it sends the request and stops when the response arrives. The only reliable optimization method is to split that clock into measured parts, fix the dominant part, and measure again.

1 · Trace one request

Separate network travel, waiting, application work, database work, and response creation.

2 · Inspect the distribution

Use p50, p95, and p99 rather than allowing an average to hide slow requests.

3 · Match mechanism to time

A Content Delivery Network, index, cache, or edge function attacks a different segment.

Percentiles show who is waiting

Sort 100 request times from fastest to slowest. A percentile is a threshold in that ordered list, not the arithmetic average.

VISUAL 2 OF 3

Why averages can mislead

A few extremely slow requests may be diluted by many fast requests. Percentiles tell you the latency threshold experienced by a chosen fraction of traffic and make a tail target testable.

Why p99 is harder to improve

The slowest requests can come from rare garbage collection pauses, overloaded servers, retries, lock contention, cache misses, or dependency failures. You must separate those causes rather than optimize the already-fast path.

CDN, database index, cache, or edge computing?

A Content Delivery Network (CDN) stores response bytes near users. Edge computing runs code near users. Neither automatically shortens a database call in the main application region.
