Beginner visual guide

Throughput counts completed work, not admitted work.

Define the operation—requests served, payments committed, messages processed—then measure how many complete per second or per minute. In a pipeline, the slowest required stage limits sustainable throughput.

1 · Name the unit

“120 successful database writes per second” is meaningful; “high throughput” is not.

2 · Find the bottleneck

Compare arrival rate, completion rate, queue growth, and utilization at every stage.

3 · Scale the owner

Replicas scale eligible reads; shards divide writes; consumers scale independent jobs.

One slow stage limits the whole pipeline

This service receives 250 requests per second. Every successful request must pass through ingress, application logic, and the database.

VISUAL 1 OF 3

Throughput versus latency

Latency is the time for one operation. Throughput is the number completed per unit time. They influence each other, but are not opposites: several operations can run concurrently, so a system can complete many slow operations each second.

Accepted is not completed

If an API puts 1,000 jobs per second into a queue but workers finish only 600, ingestion throughput is 1,000 per second while business completion throughput is 600. The 400-per-second difference becomes backlog.

Concurrency helps—until a resource saturates

Concurrency is the number of operations in progress at the same time. It can keep a system busy while some operations wait for network or disk input/output.

VISUAL 2 OF 3

Decision rule: increase concurrency while completion throughput rises and latency remains within its target. Stop when the constrained resource saturates; then reduce work, remove contention, or add/divide capacity at that resource.

Three flows, three ways to scale

Choose from the ownership of the expensive work. These mechanisms increase capacity only when the work can be distributed safely.

VISUAL 3 OF 3

What to measure before scaling

Record arrival rate, successful completion rate, error and timeout rate, queue depth over time, and utilization of CPU, disk, database connections, and locks. A growing queue is evidence that arrivals exceed sustainable completion.

What high throughput does not guarantee

It does not guarantee low latency, correct results, freshness, or availability. A batch system can complete millions of records per hour while each record waits ten minutes; a fast pipeline can also process duplicates incorrectly.

Decision rule: define the completed operation and target rate, locate the saturated stage, and scale that stage with the mechanism its work permits. Re-measure completion—not merely requests accepted at the front door.

Introduction complete

You now have three separate questions for future designs: Can the service continue through failure? How long does one operation take? How many operations can finish per unit time?
